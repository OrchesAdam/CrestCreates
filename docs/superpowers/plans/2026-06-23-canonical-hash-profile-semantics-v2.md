# Canonical Hash Profile Semantics v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement declaration-driven union canonical hash profiles and Schema required-binding hash semantics without reintroducing runtime reflection or a second hash path.

**Architecture:** The source generator remains the single shape authority: attributes declare profiles, the generator validates them and emits canonical `Utf8JsonWriter` code, and runtime only computes hashes over generated bytes. Schema optional-field visibility moves from `ContractHash` into `DefinitionHashChanged` plus descriptor-specific compatibility analysis.

**Tech Stack:** .NET 10, C# source generator in `netstandard2.0`, Roslyn diagnostics, xUnit, FluentAssertions, generated `Utf8JsonWriter` canonical JSON, no `JsonSerializer`, no `JsonTypeInfo`, no runtime reflection on the canonical hash main path.

## Global Constraints

- Breaking changes are allowed; do not preserve v1 canonical hash values.
- Do not add compatibility shims or long-lived dual paths.
- `CustomWriter` must stop being an active canonical hash profile escape hatch.
- Union exhaustiveness is a current-compilation / effectively-closed hierarchy guarantee only.
- `Filter` is collection-only semantic projection, applied before ordering and writing.
- Schema `ContractHash` v2 means required read/write binding surface, not full schema surface.
- `ContractHashChanged` and `DefinitionHashChanged` are change facts, not compatibility severity.
- Added, Removed, Deprecated, Activated, and state transitions must be classified before hash comparison.
- Existing AOT guarantees remain: no `JsonSerializer`, no `JsonTypeInfo`, no runtime reflection on the canonical hash main path.
- Deleted files must be moved to `99_RecycleBin/`, not removed directly.
